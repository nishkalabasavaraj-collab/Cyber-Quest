# CyberQuest — Project Report

## Abstract

CyberQuest is a local cybersecurity awareness game. It teaches safe habits through a knowledge quiz, fictional message checks, password strength examples, and defensive incident choices. A Java program stores player accounts and scores in a local text file. The browser interface uses HTML, CSS, and JavaScript. The project uses only the Java Development Kit and runs on one computer.

## Introduction and problem statement

People often receive suspicious messages, reuse passwords, or overlook basic security practices. CyberQuest gives students a simple place to practise recognizing these situations. It uses fictional examples and explains the reason behind each answer.

## Objectives

- Practise basic cybersecurity awareness in a safe simulation.
- Track a player's score, completed challenges, accuracy, and level.
- Demonstrate Java classes, encapsulation, inheritance-ready modules, exception handling, file handling, and a background thread.
- Provide a browser interface that is easy to present in a college demonstration.

## Scope

The Java-backed game runs locally at `http://localhost:8080`. It does not scan networks or perform attacks. Local player records are stored on the same computer. A Vercel static deployment uses browser-local storage for sample accounts and scores; its leaderboard is local to each browser and is not shared across players. This is a learning project and not a production identity or security product.

## Requirements

**Hardware:** A basic computer capable of running a browser and JDK 17 or newer.

**Software:** JDK 17+, a modern browser, and a terminal or Java IDE. No SQL database, Tomcat, Apache server, or third-party package is used.

## System design

The browser displays the interface and challenge content. In local mode it sends small form requests to the Java program, which validates account actions, updates scores, hashes passwords, and writes player records. The Java built-in `HttpServer` listens only on the local loopback address. In Vercel static mode, the browser handles the demo account and score data in local storage because Vercel does not run this Java server.

```text
Browser (HTML / CSS / JavaScript)
       | local form requests
       v
Main.java — JDK built-in HttpServer
       |             |
PlayerService     FileStorage
       |             |
     Player       data/players.txt
       ^
ProgressSaver (background Runnable thread)
```

### Class descriptions

- `Main`: Starts the local server, serves the browser files, and routes account, score, leaderboard, and password-generator requests.
- `Player`: Stores a player's ID, username, salted password hash, score, challenge count, and answer totals. Its data is private and score updates are synchronized.
- `Challenge`: An abstract parent class for quiz, phishing, password, and scenario challenges. Its child classes override `calculateScore`; Java selects the appropriate child from the challenge type.
- `PlayerService`: Registers and verifies players, records scores, and sorts leaderboard entries. Passwords are transformed with PBKDF2 before storage.
- `FileStorage`: Loads and saves tab-separated text records. It creates the data folder and file when needed and skips malformed rows.
- `ProgressSaver`: Implements `Runnable` and periodically saves records. The server interrupts and joins the thread during shutdown.
- `web/index.html`: Contains the page sections and controls.
- `web/style.css`: Defines the responsive visual design using local system fonts.
- `web/app.js`: Displays challenges, evaluates quiz responses, updates the interface, and calls the Java server.

## Modules

1. **Player access:** Register and sign in with a unique username. Passwords are hashed with a random salt; they are not written in plaintext.
2. **Quiz Arena:** Ten randomly selected questions from a bank of 30, covering six security topics. The quiz has a two-minute countdown.
3. **Phishing Detective:** Ten fictional messages classified as legitimate, suspicious, or phishing, with feedback about warning signs.
4. **Password Lab:** Evaluates a fictional sample in the browser and can request a sample generated by Java `SecureRandom`. The entered sample is not sent to the server.
5. **Defender Scenarios:** Five fictional incident situations with defensive response choices.
6. **Progress and leaderboard:** Shows accumulated points, accuracy, rank, badges, and the top ten saved players.

## Java fundamentals demonstrated

- **Encapsulation:** `Player` keeps its fields private and provides methods to read or update them.
- **Abstraction, inheritance, and overriding:** The abstract `Challenge` class defines score calculation. `QuizChallenge`, `PhishingChallenge`, `PasswordChallenge`, and `ScenarioChallenge` inherit from it and provide their own score method.
- **Polymorphism:** `Challenge.create` returns a `Challenge` reference to the selected child object. The child implementation calculates the score.
- **Classes and objects:** The services create and manage `Player` objects.
- **Exceptions:** Invalid inputs and missing players produce clear errors. File and request errors are caught so normal mistakes do not stop the server.
- **Collections and arrays:** Java uses `List<Player>` for player records. Browser challenge items use arrays.
- **Conditionals and loops:** Validation, level selection, leaderboard sorting, and challenge navigation use conditions and loops.
- **File handling:** `FileStorage` uses buffered readers and writers through Java NIO paths.
- **Threading:** `ProgressSaver` runs as a `Thread`, sleeps between saves, and stops on interruption. Synchronized methods protect shared player data.
- **Password handling:** PBKDF2 with HMAC-SHA256 and a random salt protects registered account passwords. The Password Lab sample is evaluated in the browser and is not stored.

## Algorithm and flow

1. Start the Java server and load the player file.
2. Open the local page in a browser.
3. Register or log in. Java validates the input and checks the salted password hash.
4. Select a challenge. The browser presents one question or message at a time and explains the answer.
5. Send the resulting challenge points to Java.
6. Java checks the score values, updates the player's totals, and saves the file.
7. View the profile or leaderboard. On exit, Java stops the saver thread and performs a final save.

## Demonstration commands

```text
javac --add-modules jdk.httpserver -d out src/cyberquest/*.java
java --add-modules jdk.httpserver -cp out cyberquest.Main
```

Then visit `http://localhost:8080`. Stop the server with Ctrl+C.

## Advantages and limitations

CyberQuest is easy to launch, presents multiple interactive modules, and needs no separate database or application server. Its examples are fictional and safe. It is a minor project prototype: account recovery, a shared hosted leaderboard, a secure production identity system, and detailed category-by-category reporting are outside its scope. Challenge answer evaluation is intended for learning and is not designed to prevent score tampering by a user controlling their own browser.

## Future enhancements

- Add category-specific progress and charts.
- Add more questions and challenge levels.
- Add an exportable report and instructor demonstration mode.
- Add account recovery and stronger production deployment controls if the project is expanded beyond localhost.

## Conclusion

CyberQuest provides a compact, local way to practise cybersecurity awareness. Its browser interface keeps activities clear, while Java handles accounts, scores, persistence, and background saving. The implementation is small enough to explain and extend as an MCA minor project.

## Viva questions and answers

1. **Why was Java used?** Java is portable and includes the libraries needed for files, passwords, networking, and threads. CyberQuest uses the JDK without extra frameworks.
2. **What is a class?** A class is a blueprint for objects. `Player` describes the data and actions for one player.
3. **What is an object?** An object is an instance of a class. A registered player is a `Player` object.
4. **What is encapsulation?** It keeps data and related operations together while limiting direct access. `Player` fields are private.
5. **What is abstraction?** It means showing useful operations while hiding internal details. The browser uses simple requests without handling file formats.
6. **What is inheritance?** It lets a child class reuse a parent class. The challenge classes inherit the name and score method from `Challenge`.
7. **What is polymorphism?** It lets different classes respond to the same method call in their own way. Each challenge type calculates its score through `calculateScore`.
8. **What is method overloading?** It is defining methods with the same name but different parameters. A future score helper could accept either correct answers alone or correct and total counts.
9. **What is method overriding?** A subclass provides its own implementation of a parent method. Each challenge overrides `calculateScore`.
10. **What is a constructor?** It initializes a new object. `Player` constructors initialize either new or loaded player records.
11. **What does `private` mean?** The member is accessible only inside its class. It protects `Player`'s fields.
12. **What does `synchronized` do?** It allows one thread at a time to run a protected method on the same object. Player statistics use synchronized access.
13. **What is exception handling?** It catches and handles errors so the program can respond clearly. CyberQuest catches invalid request and file errors.
14. **What is the difference between `throw` and `throws`?** `throw` sends an exception at a point in code; `throws` declares that a method may pass an exception to its caller.
15. **What is a thread?** A thread is an execution path that can run separately. CyberQuest uses a thread for periodic saving.
16. **What is `Runnable`?** It is an interface with a `run()` method that describes the work a thread performs. `ProgressSaver` implements it.
17. **What is the difference between `start()` and `run()`?** `start()` creates a new thread and then invokes `run()`. Calling `run()` directly just runs on the current thread.
18. **Why does the saver use `sleep()`?** It waits between periodic saves instead of repeatedly using processor time.
19. **Why handle interruption?** Interruption is a cooperative way to tell a thread to stop. The saver exits when the server shuts down.
20. **What does `volatile` mean here?** It makes the latest value of the `running` flag visible to the saver thread.
21. **What is a `List`?** It is a collection that can grow or shrink. `PlayerService` keeps players in a list.
22. **How is the leaderboard sorted?** It makes a copy of the player list and sorts by descending points.
23. **How are passwords stored?** A random salt and PBKDF2-derived hash are saved; the original registered password is not stored.
24. **What is a salt?** A random value mixed into password hashing so identical passwords do not produce identical stored hashes.
25. **Why is the password sample not sent to Java?** It is only for a strength demonstration, so keeping it in the browser avoids storing or transmitting it.
26. **What is `SecureRandom` used for?** It generates unpredictable values. CyberQuest uses it for registration salts and generated sample passwords.
27. **How are records stored?** `FileStorage` writes simple text rows to `data/players.txt` and reads them when the server starts.
28. **What is a local server?** It serves the page on the same computer. CyberQuest binds to `127.0.0.1` and uses port 8080.
29. **Why is there no SQL database?** This minor project uses a text file to keep storage understandable and avoid database setup.
30. **Does CyberQuest perform actual hacking?** No. Its messages and incidents are fictional awareness exercises, and it has no scanning or attack functions.
31. **What happens if a row in the save file is damaged?** The loader skips malformed rows so it can still load valid player records.
32. **How is the level chosen?** Java compares the player's total points with fixed thresholds and returns the matching rank.
33. **What is the purpose of the leaderboard?** It compares saved player scores and displays up to ten players.
34. **Why use Java's built-in HTTP server?** It lets the browser call Java locally without installing Tomcat or Apache.
35. **What does the shutdown hook do?** It requests a final save, interrupts and joins the saver thread, and stops the local server.
